# MoodMargins App Privacy worksheet

Updated October 14, 2026 for the Kickstart Exchange and Signal integrations. The developer confirmed that the previous [App Privacy label](https://appstoreconnect.apple.com/apps/6819079849/distribution/privacy) was published before this SDK was added. **Publish the new disclosures below before distributing a build containing these integrations.** Apple’s API does not expose or edit these answers. No live privacy label or hosted policy was changed by these integrations.

The Exchange Usage Data disclosures remain required. For Signal, this worksheet recommends disclosing User ID, Other User Content, and Product Interaction for App Functionality, not linked to identity and not used for tracking. The [Signal privacy guide](https://signal.kickstart.tools/guide#app-privacy) considers its infrequent, optional, explicitly submitted feedback eligible for Apple's optional-disclosure exception. This worksheet conservatively includes the actual data types rather than assuming the exception: Apple requires every criterion, including the submission form's identity presentation, to be met. No premium-status modifier is used, so Signal receives no premium flag; its manifest's supported Purchase History category does not mean this integration sends purchase history. Keep all other applicable disclosures, including Exchange's advertising purposes. [Apple's criteria](https://developer.apple.com/app-store/app-privacy-details/#optional-disclosure), [Exchange disclosure instructions](https://exchange.kickstart.tools/guide#app-privacy).

Audit scope: SwiftData/CloudKit configuration, Foundation Models request snapshots, StoreKit transaction processing, bundled dotLottie animation loading, EZSwiftData, EZCharts, GentleNotification, OnboardingKit, and KickstartSDK 0.6.0. Only the main app links Exchange and Signal; widgets and the Watch app do not. Exchange has one placement below About in Customize, hidden until entitlements resolve and while Plus is active. Signal opens from Feedback & ideas under About as a sheet, reusing the app's existing sheet host with a NavigationStack inside the sheet. Screenshot-preview mode uses SignalBoardView.demo() offline. No new package dependency, tracker, custom identifier, or premium-status reporting was added. Existing premium access rules and Watch storage are unchanged. iCloud sync still needs a real two-device test.

Exchange receives app-level configuration, bundle identifier, platform, app/build/SDK versions, and App Store country. For shipping builds it transiently verifies an Apple-signed App Transaction, then discards that signed data without retaining or using user or device values. Individual ad records last approximately 30 days; aggregate app-level statistics may be retained longer. Its network provider processes the connecting IP address to deliver traffic; Exchange does not retain it or use it to identify people. Journal content, moods, tags, AI context, and premium status are not sent to Exchange. [Exchange privacy notice](https://exchange.kickstart.tools/privacy).

Signal retains submitted requests, comments, and votes while the board exists, unless removed by the developer. Submissions can be edited or published after moderation. No journal fields, tags, moods, or AI request context are passed to Signal. The SDK handles its own app verification, temporary IP processing for abuse prevention, and required installation identifier; the host app adds none. [Signal privacy notice](https://signal.kickstart.tools/privacy).

Before release, publish the applicable App Privacy answers as **not linked to identity** and **not used for tracking**, and update the [hosted privacy policy](https://apps.transfinite.us/moodmargins/privacy-policy) using [PrivacyPolicy.txt](PrivacyPolicy.txt), which now covers both services. The advertising questionnaire remains a pending listing edit from Exchange. The local policy is a draft: verify it reflects actual practices and have a legal professional review it before publishing changes.

The local age-rating questionnaire also declares User-Generated Content and Messaging and Chat because the board distributes approved user requests/comments and supports public posting. These are pending local edits only. Review the questionnaire against the board settings you ship before applying the listing. [Apple’s capability definitions](https://developer.apple.com/help/app-store-connect/reference/app-information/age-ratings-values-and-definitions/).

Debug builds and all Simulator builds default to SignalBoardView.demo() with an offline-demo notice, even when Screenshot preview is off. TestFlight and App Store builds use the live board. For optional live development testing, launch a Debug build with --signal-live-testing and keep Screenshot preview off. The owner must separately enable Allow Xcode testing on the app's Signal dashboard with the registered bundle ID, then turn it off after testing; submissions and votes go to the real board. The app does not change that setting. Screenshot preview always forces the offline demo, including with the launch argument. TestFlight and App Review work with Allow Xcode testing off. Confirm Allow comments and voting if users should be able to interact with approved requests, and moderate incoming requests/comments in the dashboard. Offline previews require no dashboard changes and never submit to the live service.
