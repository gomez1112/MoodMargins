# MoodMargins App Privacy worksheet

Updated October 14, 2026 for the Kickstart Exchange and Signal integrations. Before the version 1.1 upload, the developer confirmed that both the updated [App Privacy label](https://appstoreconnect.apple.com/apps/6819079849/distribution/privacy) and hosted policy covering both integrations are published. The live website was independently checked and includes both services and their privacy-notice links. Label publication is based on the developer's confirmation; Apple's API does not expose those answers.

Neither the App Store Connect nor Kickstart connection exposes App Privacy editing/publishing. The developer completed that website step; the agent did not publish the label. Saving this worksheet or changing the privacy policy URL does not publish the nutrition label.

For the version containing the SDKs, the prepared answers are:

- Exchange: select Usage Data → Product Interaction and Advertising Data. For **each**, select Third-Party Advertising, Developer’s Advertising or Marketing, Analytics, and App Functionality. Answer **No** to linked to identity and **No** to tracking.
- Signal: the conservative recommendation below adds User ID and Other User Content for App Functionality, with **No** for linked to identity and tracking. Product Interaction already includes App Functionality in the Exchange answers. Signal's optional-disclosure guidance is discussed below.
- Purchase History: **do not add it solely for this Signal integration**. No `.kickstartPremiumUser` modifier or equivalent premium-status reporting is present in the app. If premium reporting is explicitly added later, disclose Purchase History for App Functionality, **not linked to identity** and **not used for tracking**, before shipping that change. This request did not enable premium reporting.
- Keep every other disclosure required by the app or another SDK. Review the product-page preview and click **Publish**, then confirm **Publish**, in App Store Connect. Apple says the answers for an app already on sale should reflect the version currently available; coordinate SDK-specific answers with that version's release.

The Exchange Usage Data disclosures remain required. For Signal, this worksheet recommends disclosing User ID, Other User Content, and Product Interaction for App Functionality, not linked to identity and not used for tracking. The [Signal privacy guide](https://signal.kickstart.tools/guide#app-privacy) considers its infrequent, optional, explicitly submitted feedback eligible for Apple's optional-disclosure exception. This worksheet conservatively includes the actual data types rather than assuming the exception: Apple requires every criterion, including the submission form's identity presentation, to be met. No premium-status modifier is used, so Signal receives no premium flag; its manifest's supported Purchase History category does not mean this integration sends purchase history. Keep all other applicable disclosures, including Exchange's advertising purposes. [Apple's criteria](https://developer.apple.com/app-store/app-privacy-details/#optional-disclosure), [Exchange disclosure instructions](https://exchange.kickstart.tools/guide#app-privacy).

Audit scope: SwiftData/CloudKit configuration, Foundation Models request snapshots, StoreKit transaction processing, bundled dotLottie animation loading, EZSwiftData, EZCharts, GentleNotification, OnboardingKit, and KickstartSDK 0.6.0. Only the main app links Exchange and Signal; widgets and the Watch app do not. Exchange has one placement below About in Customize, hidden until entitlements resolve and while Plus is active. Signal opens from Feedback & ideas under About as a sheet, reusing the app's existing sheet host with a NavigationStack inside the sheet. Screenshot-preview mode uses SignalBoardView.demo() offline. No new package dependency, tracker, custom identifier, or premium-status reporting was added. Existing premium access rules are unchanged. Release 1.1 moves Watch storage to the same private CloudKit-backed journal models and migrates existing local pages. This does not introduce developer collection of journal content. The developer confirmed publication of the updated Watch-policy wording; a fresh live-page response was checked for that wording. Actual same-account Watch/phone iCloud delivery still needs a real two-device test.

Exchange receives app-level configuration, bundle identifier, platform, app/build/SDK versions, and App Store country. For shipping builds it transiently verifies an Apple-signed App Transaction, then discards that signed data without retaining or using user or device values. Individual ad records last approximately 30 days; aggregate app-level statistics may be retained longer. Its network provider processes the connecting IP address to deliver traffic; Exchange does not retain it or use it to identify people. Journal content, moods, tags, AI context, and premium status are not sent to Exchange. [Exchange privacy notice](https://exchange.kickstart.tools/privacy).

Signal retains submitted requests, comments, and votes while the board exists, unless removed by the developer. Submissions can be edited or published after moderation. No journal fields, tags, moods, or AI request context are passed to Signal. The SDK handles its own app verification, temporary IP processing for abuse prevention, and required installation identifier; the host app adds none. [Signal privacy notice](https://signal.kickstart.tools/privacy).

Before the 1.1 upload, the developer confirmed publication of the applicable App Privacy answers as **not linked to identity** and **not used for tracking**, and the [hosted privacy policy](https://apps.transfinite.us/moodmargins/privacy-policy) was checked for both Exchange and Signal and their privacy-notice links. The complete [plain-text policy](PrivacyPolicy.txt) and [standalone HTML policy](PrivacyPolicy.html) remain the repository copies. The app has a single Privacy policy link to that website and no bundled policy screen. The advertising questionnaire is included in the version 1.1 listing changes.

The local age-rating questionnaire also declares User-Generated Content and Messaging and Chat because the board distributes approved user requests/comments and supports public posting. These are listing edits to include in version 1.1. Review the questionnaire against the board settings you ship before applying the listing. [Apple’s capability definitions](https://developer.apple.com/help/app-store-connect/reference/app-information/age-ratings-values-and-definitions/).

Debug builds and all Simulator builds default to SignalBoardView.demo() with an offline-demo notice, even when Screenshot preview is off. TestFlight and App Store builds use the live board. For optional live development testing, launch a Debug build with --signal-live-testing and keep Screenshot preview off. The owner must separately enable Allow Xcode testing on the app's Signal dashboard with the registered bundle ID, then turn it off after testing; submissions and votes go to the real board. The app does not change that setting. Screenshot preview always forces the offline demo, including with the launch argument. TestFlight and App Review work with Allow Xcode testing off. Confirm Allow comments and voting if users should be able to interact with approved requests, and moderate incoming requests/comments in the dashboard. Offline previews require no dashboard changes and never submit to the live service.
